# Legacy Desktop Tool Parity Audit

## Scope and evidence

This is a static source comparison of the original desktop modules in `D:\video-dubbing-automation\modules` with the current AutoDub services. All four requested legacy modules were available: `translator.py`, `transcriber.py`, `tts_engine.py`, and `video_editor.py`. Source evidence establishes implemented code paths, not current runtime parity or quality. No provider, FFmpeg, TTS, database, or real Project work was run for this audit.

## Reuse and protection decisions

### Legacy ideas to carry forward selectively

- Whole-transcript context for translations when it fits verified Gemini request limits.
- Deterministic source order, transcript-size-aware request strategy, and genre-aware Vietnamese localization.
- Dialogue context for pronouns, names, terminology, and adjacent narrative continuity.
- Source timestamps as read-only translation context, never as model-authored output.
- The human-oriented goal of concise translation for short speech windows, validated against meaning and a reviewed benchmark.
- The simple sequential time-shift model as a concept, while using the current authoritative planner's available-time calculation and explicit blockers.

### AutoDub protections that must remain

- Stable Segment UUIDs, immutable source text/timestamps/order checks, revision checks, and atomic full-set persistence.
- Exact structured response validation and no source-text substitution.
- TRANS-02 error classification and bounded retries; quota/permanent failures stop without switching keys/models or chunking.
- No silent TTS fallback, text truncation, fake completion, or stale Artifact publication.
- Measured normalized audio as the timeline input; current planner as the only render-readiness authority.
- Persistent Job lifecycle, safe bounded errors, controlled storage paths, and atomic Artifact publication.

### Legacy behavior that must not return

- Filling missing Vietnamese results with untranslated source text.
- Treating a partially translated transcript as successful because the missing share is small.
- Rotating keys, switching models, or trying smaller chunks after quota errors.
- TTS truncation to 250 characters or silent WAV fallback being accepted as valid speech.
- Rendering after a 1.4x cap without an explicit blocker when duration remains unresolved.
- Renderer-side unrequested hflip, logo manipulation, or subtitle-burn behavior entering the web pipeline by implication.

## TRANS-03 implementation requirements and outcome

TRANS-03's functional implementation is complete under the requirements below. The implementation status does not claim real-provider behavior or translation-quality improvement; that evidence belongs to TRANS-04.

1. Keep translation as a persisted-Segment operation and reuse stable Segment UUIDs. Build an ordered immutable snapshot containing source text and source timestamps; timestamps are context only and cannot be changed by provider output.
2. Add Bulk-First request selection: send a single full-transcript request only when a conservative, model-verified input/output budget says the complete transcript fits. Do not copy the legacy 500 Segment / 120,000 character thresholds without current model evidence. Larger transcripts use deterministic ordered batches bounded by the current configured batch/character/token policy.
3. Preserve context across calls. Prefer full-transcript context when the transcript fits. For bounded chunk mode, include an explicitly bounded read-only neighboring context or accumulated terminology/name glossary, but request output only for the target batch IDs. Never silently omit translation rows.
4. Include genre where the existing Project data provides it. Adapt the legacy Vietnamese localization, contextual pronoun, name/terminology, Manhua, and short-window concision rules into the structured prompt; do not ask Gemini to alter timestamps or ordering.
5. Return only exact `id` plus `translated_text` rows for target Segments. Reject duplicate, unknown, missing, empty, malformed, or extra-shape output for the whole transcript. No original-text fallback, partial-success threshold, or unchecked cleanup.
6. Use the TRANS-02 classifier and retry limits: quota/rate-limit fails immediately; transient network/5xx retries at most once; malformed/incomplete structured output retries the same request once; permanent errors do not retry. No key/model switching, quota fallback, or sleeps outside the bounded retry policy.
7. Validate the entire translation map before one transactional write. Recheck Project/Job revision and every Segment ID, position, source timestamp, source text, and edit state. Preserve translations/revisions on failure and never report Job success for partial output.
8. Add deterministic tests for bulk-vs-batch selection and hard budgets, context continuity across batch boundaries, timestamp immutability, exact ID mapping, duplicate/missing/extra rows, all-or-nothing persistence, edit conflicts, and TRANS-02 retry/quota behavior. Benchmark translation quality with human-reviewed meaning, continuity, names/pronouns, naturalness, and speech-window concision before claiming parity.
9. Do not expand TRANS-03 into editing/revision workflow, TTS, timeline, UI, or later-task implementation. Keep any key/model limits and quality claims tied to measured evidence.

## Open questions and evidence limits

- The legacy Python source establishes its code behavior, but this audit did not execute the desktop application or reproduce its historical test media, provider responses, model versions, or output quality.
- What Gemini model/version and token/output budget should define safe whole-transcript mode? Must be established with current provider documentation/configuration and bounded tests; the legacy code's candidate model list is not a current compatibility guarantee.
- The current `Project` model has no genre field (`backend/app/models/entities.py:53-76`). TRANS-03 cannot pass Project genre unless it is available from another existing input; adding persisted genre would require a separate explicit scope/schema decision.
- How large a neighboring context window materially improves cross-batch continuity without causing source instruction injection or excessive tokens? Unit tests can validate request construction; quality requires a reviewed benchmark.
- Should initial TTS ever adopt the legacy >5 WPS +35% tier, or should it remain an explicit optimization choice? Requires comparative listening and timing evidence; this audit makes no recommendation to change the accepted current default.
- Current AutoDub render output has no subtitle burn-in, while legacy renderer generated and shifted SRT/ASS. Whether that is a product requirement is not established by this task.
- No runtime parity, provider quality, TTS playback, ASR quality, FFmpeg output, database, or real-Project claim is made here.
